1. المقدمة (Introduction)

1.1 معلومات عن محتويات التقرير وتسلسل الأقسام

يقدم هذا التقرير وثيقة هندسية وفنية شاملة لمشروع تطوير تطبيق الأندرويد "شُغل - WORK". يتطرق التقرير إلى دراسة خلفية المشروع ودوافع تطويره، مروراً بالدراسات السابقة والابتكارات البرمجية المعتمدة، ثم يفصّل في الهيكلية البرمجية (Architecture)، وخوارزميات المطابقة الذكية، والربط السحابي الحقيقي مع سحابة Firebase، وهياكل البيانات المستعملة، وتفاصيل قواعد البيانات NoSQL، مع توثيق كود الجافا (JavaDocs)، ودليل استخدام تفصيلي مصوّر، والآثار التعلمية والمهارية المكتسبة خلال الرحلة.

1.2 من أين جاءت فكرة المشروع (خلفية المشروع)

جاءت فكرة مشروع "شُغل - WORK" من واقع التحديات الاقتصادية والتحول الرقمي المتسارع نحو العمل الحر المستقل (Freelancing) وتقديم الخدمات المصغرة والمهنية. يُعاني الكثير من الشباب والمهنيين والطلاب أصحاب المهارات (في البرمجة، التصميم، الترجمة، التسويق، الصيانة) من صعوبة الوصول إلى العملاء المحليين وتكاليف التسويق العالية. في المقابل، يواجه العملاء صعوبة في إيجاد مقدمي خدمات موثوقين بأسعار تناسب ميزانياتهم المحددة.

من هنا نشأت الحاجة لبناء منصة أندرويد تفاعلية ومباشرة تجمع بين العميل (Client) ومقدم الخدمة (Provider) عبر بيئة عمل مرنة توفر المزامنة اللحظية، والبحث الذكي بالميزانية، والمحادثات المباشرة، مع خيارات التواصل الفوري عبر الواتساب والمكالمات.

1.3 دراسة أولية والابتكار الجديد بالمشروع

عند دراسة سوق التطبيقات الحالية (مثل خمسات، مستقل، Fiverr، Upwork)، وُجد أنها تعتمد بنسبة كبيرة على واجهات ويب أو تطبيقات معقدة ذات إجراءات تسجيل طويلة وعمولات عالية ونظام بحث تقليدي يعتمد فقط على النصوص والكلمات المفتاحية.

💡 الإضافات والابتكارات الجديدة في تطبيق "شُغل - WORK":
  • خوارزمية التقارب في السعر والميزانية (Smart Price Proximity Matching Algorithm): لا يكتفي التطبيق بالبحث عن اسم الخدمة فقط، بل يستقبل الميزانية المستهدفة من العميل بالدولار ($)، ويقوم بحساب نسبة التقارب والانحراف في السعر وعرض الشارات التوضيحية (مثل: "مطابق لميزانيتك بالضبط 🎯" أو "أقل من ميزانيتك بـ $10 💡").
  • نظام المزامنة اللحظية ثنائية الاتجاه (Realtime Multi-Device Sync): الربط المباشر بـ Firebase Realtime Database بحيث أي خدمة يتم طرحها، أو أي طلب يتم إرساله، أو أي تغيير في حالة الطلب (قبول/رفض/إكمال) يظهر فوراً على أجهزة جميع المستخدمين الآخرين المفتوح عندهم التطبيق بدون الحاجة لتحديث الصفحة.
  • نظام الدردشة المباشرة المدمج في التطبيق (In-App Realtime Chat System): توفير شات فوري حقيقي داخل التطبيق مع حفظ وتزامن الرسائل بين العميل والمزود لحظياً عبر السحابة.
  • الدمج بين التواصل الداخلي والتواصل المباشر عبر الواتساب (Dual Communication Channels): إمكانية الانتقال بزر واحد من التطبيق إلى محادثة واتساب مجهزة برقم الهاتف والرسالة الترحيبية التلقائية.

1.4 دراسات سابقة وإطار نظري

تمت دراسة وتحليل عدة منصات سابقة للوقوف على إيجابياتها وسلبياتها:

  • منصة خمسات (Khamsat): منصة عربية ممتازة للخدمات المصغرة، لكنها تعتمد على الموافقة اليدوية وتأخر التحديثات وبطء التواصل المباشر بين الطرفين قبل الشراء.
  • تطبيق Fiverr: منصة عالمية ضخمة لكنها معقدة الواجهات وتفتقر إلى خيار البحث المباشر بالنطاق السعري التقريبي المرن.
  • تطبيق Upwork: مخصص للمشاريع الكبيرة والأنظمة المعقدة، ولا يناسب أصحاب المهن والخدمات السريعة والمحلية.

الاستفادة والتطوير في مشروعنا: تم بناء نموذج مبسط وسريع ومباشر يقلل الاحتكاك (Low Friction)، ويركز على الأداء الفائق والواجهات العصرية المصممة وفق Material Design 3، مع دعم الدخول المباشر واختيار الدور (عميل أو مقدم خدمة) في ثوانٍ معدودة.

1.5 التحديات التي واجهتني خلال المشروع وكيف تغلبت عليها

  1. تكرار معرفات الإضافات وتعارض Gradle Plugins: حدوث خطأ Plugin with id 'com.android.application' was already requested بسبب تكرار الاستدعاء في build.gradle.kts. تم حله بتنظيف وإصلاح ملفات التجميع.
  2. مشكلة عدم تطابق أسماء الحزم (Package Mismatch): ظهور خطأ :app:processDebugGoogleServices بسبب اختلاف اسم الحزمة في google-services.json عن applicationId. تم تعديل اسم الحزمة إلى com.example.work.
  3. تحدي المزامنة الحية وعناوين الفايربيس (Multi-Region Database URLs): تعامل التطبيق مع عناوين الفايربيس المخصصة (work-4451a-default-rtdb) وتم بناء صف FirebaseHelper الذكي للتعامل مع النطاقات الجغرافية المختلفة (US, EU, Asia).
  4. تخزين الصور المرفقة ومشاركتها سحابياً دون خادم إضافي: تطوير خوارزمية ضغط وتقليص أبعاد الصور وتحويلها إلى سلاسل Base64 String لتخزينها مباشرة في سحابة Realtime Database وعرضها بسلاسة على كل الأجهزة.
  5. إدارة صلاحيات الفايربيس وتنبيهات المستخدم: معالجة استجابات Permission denied من خلال القواعد التلقائية وعرض تنبيهات توست شفافة على الشاشة.

1.6 المشكلة التي يعالجها المشروع والحاجة لها

يعالج المشروع مشكلة الفجوة بين العرض والطلب في سوق الخدمات المصغرة والمهن الحرة. يحتاج العميل لوسيلة سريعة للبحث عن المهارات بأسعار متقاربة مع ميزانيته بدون المماطلة، بينما يحتاج صاحب المهارة إلى لوحة تحكم مجانية وسريعة لعرض خدماته وإدارة الطلبات الواردة والمحادثات من هاتفه مباشرة.

1.7 سبب اختيار الموضوع

اخترت هذا الموضوع لشغفي الشخصي الشديد بتطوير تطبيقات الهواتف الذكية بلغة Java، ونتيجة الملاحظة الميدانية لوجود حاجة ماسة لدى زملائي والشباب لأداة تجمع أصحاب المهارات بالعملاء المحليين بدعم للعملات واللغة العربية.

3. الخوارزميات المبتكرة والمطابقة الذكية

3.1 خوارزمية المطابقة الذكية بحسب تقارب الميزانية (Price Proximity Matching Algorithm)

تعمل هذه الخوارزمية داخل ServiceRepository.java لتفلترة وترتيب الخدمات بحسب الميزانية التي يحددها العميل بالدولار ($):

// الكود البرمجي المباشر للخوارزمية من ServiceRepository.java
public synchronized List<ServiceItem> searchServices(String query, double targetPrice, String category) {
    List<ServiceItem> filtered = new ArrayList<>();
    String q = query != null ? query.trim().toLowerCase() : "";

    for (ServiceItem item : servicesMap.values()) {
        boolean matchesQuery = q.isEmpty() ||
                (item.getTitle() != null && item.getTitle().toLowerCase().contains(q)) ||
                (item.getDescription() != null && item.getDescription().toLowerCase().contains(q));

        boolean matchesCategory = category == null || category.equalsIgnoreCase("الكل") ||
                (item.getCategory() != null && item.getCategory().equalsIgnoreCase(category));

        boolean matchesPriceRange;
        if (targetPrice > 0) {
            double diff = Math.abs(item.getPrice() - targetPrice);
            double maxAllowedDiff = Math.max(25.0, targetPrice * 0.40);
            matchesPriceRange = diff <= maxAllowedDiff;
        } else {
            matchesPriceRange = true;
        }

        if (matchesQuery && matchesCategory && matchesPriceRange) {
            filtered.add(item);
        }
    }

    if (targetPrice > 0) {
        filtered.sort((o1, o2) -> {
            double diff1 = Math.abs(o1.getPrice() - targetPrice);
            double diff2 = Math.abs(o2.getPrice() - targetPrice);
            return Double.compare(diff1, diff2);
        });
    }

    return filtered;
}

3.2 خوارزمية ضغط وتقليص أبعاد الصور إلى Base64 String

تستخدم في AddServiceActivity.java لتحويل صورة المعرض المرفقة لسلسلة نصية خفيفة الوزن لتخزينها بالسحابة:

private String uriToBase64(Uri uri) {
    if (uri == null) return null;
    try {
        InputStream inputStream = getContentResolver().openInputStream(uri);
        Bitmap bitmap = BitmapFactory.decodeStream(inputStream);
        if (inputStream != null) inputStream.close();
        if (bitmap == null) return null;

        int maxDim = 500; // تقليص الأبعاد القصوى إلى 500 بكسل
        int width = bitmap.getWidth();
        int height = bitmap.getHeight();
        if (width > maxDim || height > maxDim) {
            float ratio = Math.min((float) maxDim / width, (float) maxDim / height);
            width = Math.round(width * ratio);
            height = Math.round(height * ratio);
            bitmap = Bitmap.createScaledBitmap(bitmap, width, height, true);
        }

        ByteArrayOutputStream baos = new ByteArrayOutputStream();
        bitmap.compress(Bitmap.CompressFormat.JPEG, 70, baos); // ضغط جودة الصورة إلى 70%
        byte[] bytes = baos.toByteArray();
        return Base64.encodeToString(bytes, Base64.DEFAULT);
    } catch (Exception e) {
        return null;
    }
}

4. الربط السحابي وقواعد البيانات (Firebase & Database Details)

4.1 الشبك على خوادم Firebase السحابية

تم الشبك بـ Firebase Realtime Database و Firebase Authentication عبر الصف المطور FirebaseHelper.java:

public class FirebaseHelper {
    private static final String TAG = "FirebaseHelper";
    private static final String DB_URL_US = "https://work-4451a-default-rtdb.firebaseio.com";
    private static FirebaseDatabase databaseInstance;

    public static synchronized FirebaseDatabase getDatabase() {
        if (databaseInstance == null) {
            try {
                databaseInstance = FirebaseDatabase.getInstance(DB_URL_US);
                databaseInstance.setPersistenceEnabled(true);
            } catch (Exception e) {
                databaseInstance = FirebaseDatabase.getInstance();
            }
        }
        return databaseInstance;
    }

    public static void ensureAuthenticated(OnAuthCompleteListener listener) {
        FirebaseAuth auth = FirebaseAuth.getInstance();
        if (auth.getCurrentUser() != null) {
            if (listener != null) listener.onAuthSuccess();
            return;
        }

        auth.signInAnonymously().addOnCompleteListener(task -> {
            if (task.isSuccessful()) {
                Log.d(TAG, "Signed in anonymously to Firebase Auth successfully!");
            }
            if (listener != null) listener.onAuthSuccess();
        });
    }
}

  2. تصفح وطرح الخدمات: يستطيع المزود طرح خدماته مع إضافة الصور والسعر بالدولار، بينما يستطيع العميل تصفح الخدمات والتصنيفات والبحث بالميزانية.
  3. إرسال الطلب وإدارته: يطلب العميل الخدمة مع إدخال هاتف التواصل، فتظهر فوراً في تبويب "الطلبات الواردة" لدى المزود مع خيارات القبول/الرفض والإكمال.
  4. الدردشة المباشرة (In-App Chat): يمكن لأي طرف النقر على "مراسلة بالتطبيق 💬" لبدء شات سحابي مباشر بالوقت الفعلي.

6. أثر المشروع والمراجع العلمية (Impact & References)

6.1 أثر المشروع عليّ والشغف الشخصي

أكسبني هذا المشروع خبرة عميقة وعملية في بناء تطبيقات أندرويد متكاملة تحاكي الأنظمة الواقعية. تعلمت كيفية إدارة دورة حياة الواجهات (Activity Lifecycle)، وبناء واجهات مرنة باستخدام Material Design 3، واستخدام Firebase Realtime Database وتصميم قواعد البيانات الشجرية NoSQL، وتفعيل المزامنة المباشرة وتشفير الصور.
